# 20대 결함 카탈로그

## 문서 역할

이 문서는 LLM 및 다중 에이전트 코딩 시스템에서 관찰되는 **표면 증상**만 기록한다. 해결책이나 구현 기술은 쓰지 않는다. 이 문서의 목적은 "무엇이 잘못되는가"를 빠르게 식별하는 것이다.

근본 원인 분류는 [02_9_root_causes.md](/C:/syszone_project/ui_design/docs/theory/02_9_root_causes.md)에서 다룬다.

## 읽는 법

각 결함은 같은 포맷으로 정리한다.

- `원리`: 왜 이 현상이 나타나는가
- `증상`: 실제 개발 현장에서 어떤 식으로 드러나는가

## 결함 분류

### A. 단일 개체 수준 결함

#### 1. 극단적 게으름
- 원리: LLM은 출력 토큰과 탐색 비용을 줄이는 방향으로 기울어지며, 구조적 분리보다 가장 짧은 경로를 택한다.
- 증상: 모듈형 설계를 지시해도 단일 파일에 모든 책임을 밀어 넣고, 인간이 강제하지 않으면 스스로 구조화를 시도하지 않는다.

#### 2. 무지성 아부와 뻔뻔한 환각
- 원리: RLHF 계열 모델은 진실보다 사용자와의 정렬을 우선시하는 경향이 있다.
- 증상: 잘못된 가정 위에서도 반박하지 않고 맞장구치며, 존재하지 않는 API나 로직을 확신에 차서 제시한다.

#### 3. 세션 단절과 단기 기억 상실
- 원리: 긴 컨텍스트에서 초기 제약 조건의 가중치가 약해진다.
- 증상: 조금 전 선언한 변수명, 스키마, 규약을 금세 잊고 세션이 끊길수록 import/undefined 오류가 누적된다.

#### 4. 무자비한 토큰 연소기
- 원리: 기억 상실을 막으려면 컨텍스트를 반복 주입해야 하는 구조가 생긴다.
- 증상: 사소한 수정에도 거대한 코드베이스를 계속 다시 넣게 되어 비용이 폭증한다.

#### 5. 외과적 수술 불가 및 파괴적 덮어쓰기
- 원리: 핀포인트 수정보다 넓은 재생성을 택하는 경향이 강하다.
- 증상: 작은 스타일 변경을 요청해도 멀쩡한 비즈니스 로직까지 함께 훼손한다.

#### 6. 수조 속의 장님 뇌
- 원리: 모델은 텍스트만 보고 세계를 추정하며, 실제 실행 환경을 체험하지 못한다.
- 증상: UI 깨짐, 런타임 타임아웃, DB 데드락 같은 현실의 실패를 스스로 감지하지 못한다.

#### 7. 브레이크 고장 난 폭주 기관차
- 원리: 자기회귀 생성은 이미 내뱉은 경로를 쉽게 버리지 못한다.
- 증상: 초기에 설계가 꼬여도 다시 시작하지 않고 예외 처리만 덧칠하며 더 큰 스파게티를 만든다.

#### 8. 확률론적 무질서
- 원리: 동일 입력에서도 결과가 요동치는 비결정성이 있다.
- 증상: 파일 구조, 패턴, 계약이 매번 달라져 일관된 파이프라인 유지가 어렵다.

#### 9. 과거에 갇힌 시한폭탄
- 원리: 모델 지식은 특정 과거 시점에 동결되어 있다.
- 증상: 낡은 문법, 폐기된 라이브러리, 존재하지 않는 의존성을 최신 해법처럼 제시한다.

#### 10. 가짜 논리 엔진
- 원리: 기호주의적 연역이 아니라 패턴 모사에 의존한다.
- 증상: 겉보기에는 그럴듯하지만 엣지 케이스에서 붕괴하는 가짜 알고리즘을 생성한다.

### B. 다중 개체 협업 결함

#### 11. 비잔틴 합의 붕괴
- 원리: 비결정론적 개체들은 충돌 상황에서 안정적 합의 메커니즘을 갖지 못한다.
- 증상: 에이전트들이 서로 책임을 전가하며 코드를 덮어쓰고, 핑퐁 데드락에 빠진다.

#### 12. 역할 경계 위반 및 시간적 조정 실패
- 원리: 프롬프트 기반 역할 분리는 세션이 길어질수록 약해진다.
- 증상: 한 에이전트가 자기 책임을 넘어서 재설계를 시도하거나, stale state 위에서 작업한다.

#### 13. 정보 은닉 및 컨텍스트 파편화
- 원리: 상대가 무엇을 모르는지 추론하고 선제 공유하는 능력이 약하다.
- 증상: 우회 로직, 크리덴셜, 핵심 상태가 다음 단계로 전달되지 않아 파이프라인이 분절된다.

#### 14. 에코 체임버 및 순응 편향
- 원리: 에이전트들은 지배적인 출력에 순응하기 쉽다.
- 증상: 잘못된 설계가 내부 비판 없이 강화되어 조직적 환각으로 굳어진다.

#### 15. 프롬프트 감염 및 은닉 채널 형성
- 원리: 데이터와 명령을 동일한 자연어 흐름으로 처리한다.
- 증상: 외부 로그나 주석 속 문장이 제어 명령처럼 해석되거나, 에이전트 간 비표준 통신 패턴이 형성된다.

#### 16. 합성 데이터 순환과 이기적 모델 붕괴
- 원리: 자기 생성 산출물을 재귀적으로 재사용하면 구조적 품질이 평균으로 붕괴한다.
- 증상: 초기에는 복잡한 구조를 만들다가도 시간이 지나면 단순하고 조악한 패턴만 남는다.

### C. 장기 운영 및 검증 결함

#### 17. 의미론적 표류와 인식론적 부채
- 원리: 전체 의도보다 눈앞의 에러 제거에 최적화된다.
- 증상: 임시 패치가 누적되어 인간도 해석하기 어려운 구조적 부채가 쌓인다.

#### 18. 장기 궤적 이탈과 아키텍처 부패
- 원리: 장기 프로젝트에서 초기 아키텍처 원칙을 붙들어둘 내재적 닻이 없다.
- 증상: 수많은 자율 수정 끝에 원래 의도는 사라지고 프랑켄슈타인 구조만 남는다.

#### 19. 표면적 검증 및 합의 오도
- 원리: 검증자도 깊은 논리 무결성보다 표면적 체크리스트에 기대기 쉽다.
- 증상: 기능적으로 망가진 코드가 "컴파일 성공"만으로 승인된다.

#### 20. 도구 오용 및 인터페이스 환각
- 원리: 외부 도구의 문법과 제약을 안정적으로 내면화하지 못한다.
- 증상: 존재하지 않는 엔드포인트 호출, 잘못된 인자 조합, 해결 불가능한 작업을 끝없이 계속 시도한다.
